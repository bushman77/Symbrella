# Hippocampal–cortical consolidation: first slice (experimental)

## Principle

Symbrella must distinguish three different kinds of information:

1. **Experience** — hippocampal episodes and past conversational responses;
2. **Supported knowledge** — a conclusion independently derived by Core from
   source-backed premises (not generated by Qwen);
3. **Unresolved issues** — missing premises, contradictory observations or a
   failed inference. An issue is not a fact, however frequently it is recalled.

Curiosity runs as an independent OTP process. Its relevance here is future
**issue selection and investigation**, not an unrestricted permission to
read/write knowledge or run external tools. The first slice exposes a bounded
read-only issue queue but does **not** automatically schedule replay, searches,
or autonomous fact verification.

## What is implemented now

- `Db.ConsolidatedConclusion` — new durable proof/premise ledger, intentionally
  separate from lexical `Db.BrainCell` and episodic `Db.Episode`.
- `Core.Response.Consolidation.capture/2` — stores **only** an exact,
  authorized population-comparison conclusion from Core. Stores the pair of
  original dated source claims, URLs, and deterministic derivation, *never*
  the LLM's prose.
- `Core.Response.Consolidation.recall/1` — finds eligible stored historical
  premises, reconstructs the evidence, rederives the winner and difference,
  and reruns existing response authorization before reuse. A new session and
  an offline LLM can still receive a Core-authored answer.
- `Db.CognitiveIssue` and `Db.CognitiveIssues` — durable, idempotent,
  prioritized issues for contradictory stored premises, invalid derivation,
  and missing dated evidence.
- `Core.Curiosity.UnresolvedIssues.candidates/1` — bounded read-only
  introspection for the separate curiosity loop. No implicit intervention.
- A newly authorized exact-year proof can resolve a missing-year issue.
  Contradictory proofs stay unresolved until a separate adjudication mechanism
  can evaluate them.
- No reuse for questions requesting *current/latest* figures, or dates that
  do not match the stored reference year. Such requests go to the normal
  retrieval route; stored history must not impersonate a fresh source.

## Safety / activation

This capability is **disabled by default**:

```elixir
config :core, :symbolic_consolidation_enabled?, false
```

Before enabling it on a development database, run its additive migrations:

```bash
cd ~/Symbrella
git pull --ff-only origin development
mix db.migrate
```

The schema changes create the tables `consolidated_conclusions` and
`cognitive_issues`; there is no reset, drop, or re-import operation.

Run the targeted tests, which migrate their isolated test database through
the umbrella `mix test` alias:

```bash
mix test apps/core/test/core/response/symbolic_consolidation_test.exs --trace
```

For a running `iex -S mix phx.server`, enable the experimental path:

```elixir
Application.put_env(:core, :symbolic_consolidation_enabled?, true)
```

To inspect pending issues without granting autonomous authority:

```elixir
Core.Curiosity.UnresolvedIssues.candidates(10)
```

To revert behavior, set the flag to `false`. Existing persisted records
remain for audit; the system no longer reads or creates these proof records
when disabled.

## Constraints and next phase

This is **not** yet general semantic learning. The implementation only
consolidates two-location population comparisons that already passed
`Core.Response.AuthoritativeAnswerPlan`. It does not replay arbitrary
hippocampal episodes, generalize from LLM answers, connect a scheduler to the
curiosity loop, or periodically refresh source evidence.

The logical next interface is a supervised, budgeted curiosity investigation:

```text
Curiosity proposal
  → select prioritized unresolved issue
  → choose permitted investigation action
  → fetch independent dated evidence
  → validate/rederive using Core's existing gate
  → either consolidate knowledge, mark resolved, or retain open issue
```

The critical invariant is that **attempted investigation, repeated replay,
and model confidence never count as independent verification**. Keep issue
provenance and unresolved status visible until the appropriate proof exists.
